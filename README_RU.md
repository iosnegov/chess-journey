# Chess Journey: Python Chess Game with Custom GUI and AI

*Полностью переработанный школьный проект, созданный на основе серии туториалов ["Chess Engine in Python" от Eddie Sharick](https://www.youtube.com/watch?v=EnYui0e73Rs&list=PLBwF487qi8MGU81nDGaeNE1EnNEPYWKY_).*

## Краткое описание

В этом проекте реализована полная логика шахматных правил с помощью библиотеки [python-chess](https://github.com/niklasf/python-chess), собственный графический интерфейс (GUI), построенный на [pygame-ce](https://github.com/pygame-community/pygame-ce) и [pygame-gui](https://github.com/MyreMylar/pygame_gui). Конфигурация аккуратно управляется через [Pydantic Settings](https://github.com/pydantic/pydantic-settings). Кроме того, проект имеет глубокую интеграцию с мощным движком [Stockfish](https://stockfishchess.org/), что позволяет играть как против компьютера, так и с другом за одним устройством.

## Инструкция по установке и запуску

### I. Предварительные требования

| Компонент | Требование |
| :--- | :--- |
| **Менеджер пакетов** | [`Pixi`](https://pixi.prefix.dev/latest/) |
| **Операционная система** | GNU/Linux-система |
| **Архитектура** | `x86_64` |

> **Примечание:**  
> Это не строгие требования, а базовое окружение, в котором код гарантированно работает «из коробки». Возможны альтернативные настройки, но они могут потребовать ручной конфигурации.

### II. Установка и настройка

1. **Клонирование репозитория**

    ```bash
    git clone https://github.com/snegoviol/chess-journey.git
    cd chess-journey
    ```

2. **Установка зависимостей и настройка окружения**

    ```bash
    pixi install
    pixi run copy-env
    ```

3. **Настройка Stockfish**
   - Скачайте подходящий [бинарный файл Stockfish](https://stockfishchess.org/download/) для вашей платформы.
   - Поместите исполняемый файл в директорию `src/chess_game/assets/stockfish/`.
   - При необходимости проверьте или обновите путь к файлу в конфигурационном файле `.env`.

### III. Запуск

После завершения настройки шахматную игру можно запустить одной командой:

```bash
pixi run launch-chess-game
```

> **Хотите лучше понять систему?**  
> Если вас интересует внутренняя архитектура, ознакомьтесь с подробной [документацией по архитектуре](docs/architecture_ru.md).

### IV. Оригинальная версия (Опционально)

Если вы хотите изучить или запустить оригинальную версию кодовой базы, вы можете настроить и запустить ее с помощью следующих команд:

```bash
pixi run setup-legacy-images
pixi run launch-legacy-code
```

## Известные проблемы

- **Рокировка в Chess960**  
Рокировка в вариантах Chess960 не работает из-за конфликта обработки ввода в графическом интерфейсе. Рокировка в Chess960 требует перемещения короля на клетку ладьи, но текущий обработчик кликов мыши выбирает фигуру ладьи на этой клетке вместо того, чтобы обработать её как допустимую клетку назначения для хода короля, что предотвращает выполнение рокировки. Однако, когда ИИ делает ход рокировки, он работает корректно, поскольку ИИ использует библиотеку `python-chess` напрямую.

- **GameScreen.update()**  
Метод `update()` нигде явно не вызывается в коде, но по какой-то причине он необходим для корректного отображения таймеров. Удаление этого неиспользуемого метода нарушает способность таймера правильно отображать текущие значения времени.

- **Настройки ИИ**  
По текстовым полям ввода можно кликнуть, когда активны настройки ИИ (визуальный баг, ввод текста при этом не происходит).

## Возможные улучшения

- **Улучшенный интерфейс слайдеров**  
Слайдеры в настоящее время не отображают свои текущие числовые значения. Было бы отлично добавить визуальную обратную связь, показывающую текущее значение, и в идеале обновлять его в реальном времени при перетаскивании ползунка, обеспечивая мгновенную реакцию на изменение параметров.

- **Запись ходов**  
Реализовать корректную запись и отображение ходов игры в стандартной шахматной нотации. В оригинальном коде туториала была базовая функциональность отображения ходов, но эта функция была намеренно опущена при переработке, чтобы сосредоточиться на улучшениях основной архитектуры. Добавление этого функционала вернуло бы пользователям полную историю игры.

- **Надежная обработка ошибок**  
Добавить корректную валидацию пользовательских настроек и реализовать комплексную проверку на `None` во всем коде для повышения стабильности приложения.

- **Полноценное превращение пешки**  
Расширить механику превращения пешки для поддержки всех типов фигур, а не только ферзя.

- **Правильное управление компоновкой UI**  
Заменить жестко заданные позиции, размеры и отступы на полноценную систему компоновки (layout system) для виджетов и экранов.

- **Темы PyGame GUI**  
Добавить поддержку тем PyGame GUI для улучшения визуального оформления и пользовательского опыта.

## Конец путешествия

Этот проект никогда не задумывался как законченное шахматное приложение. Он создавался как учебный проект с целью обучения через практику. Изначально проект ставил целью создание минимально жизнеспособного продукта (MVP), демонстрирующего современные практики разработки на Python, объектно-ориентированную архитектуру и интеграцию с современными библиотеками, такими как `python-chess`, `pygame-ce` и `pygame_gui`.

[Известные проблемы](#известные-проблемы) и [Возможные улучшения](#возможные-улучшения), описанные выше, были намеренно оставлены без исправлений как осознанные решения, принятые в духе быстрой разработки. Более того, создание полнофункциональной игры на PyGame подразумевает использование Python, а выбор Python для игр — сомнительное решение, когда для серьезной разработки игр существуют специализированные высокопроизводительные альтернативы, такие как [Godot](https://github.com/godotengine/godot).
